## Tech & structure
- Godot **4.7.2** (user's version), GDScript only, GL Compatibility renderer (PC + mobile). Base viewport 1280x720, stretch `canvas_items`/`expand`.
- `scenes/main.tscn` + `scripts/main.gd` — app shell; applies theme, hosts the current screen.
- Autoloads: `Data` (`scripts/core/data.gd`, loads `data/*.json`), `Router` (`scripts/core/router.gd`, `Router.go("screen_id")`; register screens in `SCREENS`), `Game` (`scripts/core/game.gd`, current athlete + today's date; career starts Mon 2 Nov 2026).
- `Athlete` (`scripts/core/athlete.gd`): attributes are floats 1–20 keyed by id from `data/attributes.json`; `to_dict`/`from_dict` for saving. `AthleteFactory` builds the 14-year-old from creation choices (base ranges + background answer effects from `data/background_questions.json`; `create` = before the points). **Points pool (GDD 4.1.1 "Built (points pool)"):** pool = `pool.base` 6 + the answers' `experience` (6–16), max +3 each (`cap()`); experience moves trainability ((5 − exp) × 0.7) and every physical attribute ((exp − 5) × 0.12); `pool_for / pool_parts / coach_spread / spend / estimate` (the coach's guess: 800 m time + rival-pool percentile, texts in the file's `estimate`) / `weight_tier` (dots per attribute from races.json `ability_weights`) / `background_effects / experience_shift / experience_note`. Wizard (`new_career.gd`): pool breakdown, guess, dots, "Let the coach spread them" / Clear, a changed story resets the points; the summary shows where it came from. Spread of starting athletes: `tools/start_spread.gd [-- n]` (500 athletes + three fixed stories; the median with the coach's spread sits at the 51st percentile of the rival pool).
- **Responsive UI:** `Layout` (`ui/layout.gd`) holds `Layout.compact` (true for a portrait/squarish window, i.e. phone). `main.gd` picks the mode on every window resize, sets the window `content_scale_size` (wide: 1280x720-based, scale floor 0.7; compact: 480 px logical width), rebuilds the theme (`ThemeBuilder.build(compact)`) and emits `Router.layout_changed`. Every screen builds its layout from `Layout.compact` and rebuilds on that signal (hub, wizard, race, load game, main menu). Rules: use `UIKit.flex()` (BoxContainer that is a row on PC, a column on phone), `Layout.page_margin()`, 44 px minimum for anything tappable, **no hover-only info** (use `UIKit.attr_row(..., description)` / `UIKit.tap_to_explain` and `ChoiceCard` instead of tooltips). Hub: tabs on top (`TabButton`) on PC, bottom bar (`BottomTabButton`) on phone. Race decisions are a card beside the track (PC) or a bottom sheet (phone), never covering the track. Check with `tools/layout_check.gd` (live-resizes through 1280x720, 720x1280, 390x844, 1000x900, 844x390) and `screenshot_tour.gd --resolution 390x844`.
- **Backdrop:** `scripts/ui/backdrop.gd` + `ui/backdrop.gdshader` draw the background gradient; a photo in `assets/backgrounds/<screen_id>.jpg` (or `default.jpg`) is shown blurred and darkened (see the README there). Three CC BY-SA photos are included (Forss + Kuivisto at Kalevan Kisat 2018 by Tuomas Vitikainen, Lahti Stadium by Kallerna; credits in that README, still needs an in-game Credits screen). Their `.import` files must keep `mipmaps/generate=true` (the blur samples a mip level). Panels are slightly translucent (`Palette.SURFACE_PANEL`).
- **Help (GDD 5 "Help"):** texts only in `data/help.json` (`screens` + `topics`, sections ≤ ~50 words, `see` = topic links, `version`); `Help` (`scripts/ui/help.gd`: `entry / is_new / mark_seen`, "read" in `user://help_seen.cfg`, tools set `Help.SEEN_PATH`), `HelpButton` (44 px "?", "new" dot, `entry_id`), `HelpPanel` (the content, `stack` for See also / Back), `HelpOverlay.open(host, id)` (phone sheet / PC right panel over a screen). Hub: header "?" → `_help_entry()` (tab, Training page), PC = the side slot over the day editor, phone = overlay; day editor `help_requested`; race screen `_help_id()` by stage (the race waits); wizard; `HealthEventPanel.build(..., on_help)`. `Layout.stacked()` = phone or PC with the hub's side panel open (Training pages stack their rows; the hub rebuilds them when the panel opens/closes). Check: `tools/help_check.gd` (every "?" pressed, every entry used; **headless it gets a phone-sized window and tests only the phone layout** (493 checks): run it windowed, `--rendering-driver opengl3 --resolution 1280x720`, for the PC layout (520 checks, 513 on the phone layout; the old "day editor ?" failure was the check's own bug, fixed)).
- Screens built in code use `UIKit` (`scripts/ui/ui_kit.gd`) helpers: labels, panels, toggles, FM-style `attr_row` with value colours.
- Screens: `scenes/screens/*.tscn` (mostly just a root node now) with scripts in `scripts/ui/`; the hub, wizard and race screen build their shell in code so it can switch layout.
- Theme is built in code: colours/sizes in `ui/palette.gd`, styles in `ui/theme_builder.gd`. Label variations: TitleLabel, HeadingLabel, MutedLabel, CaptionLabel; button variation: PrimaryButton. Font: Inter (`assets/fonts`, OFL).

Rivals: `Rivals.train_week(pool, gender, monday, birth_year)` × `growth_by_age` (races.json `rivals`), no growth above the ceiling (`ceiling_max` 17.5). Championships: `competitions.json` `field` per age class and gender (real 2026 entries) → `RaceDay.entry_range` → `Rivals.pick_field(..., entries)` (`races.json` `fields.championship`). Race-day form × `Race.form_age_share(Race.age)` (`engine.form_sd.by_age`; RaceDay sets `age`; tools that make races alone leave 0 = unchanged). `Calendar.SEASONS_AHEAD` 20, `Calendar.season_offset` (whole weeks nearest to the years). Tools: `tools/career_check.gd -- <n per kind> [kinds] [seasons] [first] [rows] [norace] [data.path=value]` (7 seasons ~2 min per athlete with races, ~35 s `norace`; 4 lanes of 8 athletes per kind ~35 min; pairs = athlete i of every kind has the same rolls), `tools/rival_curves.gd -- <pools> [male|female|both] [key=value,growth_male=14.5:0.55|...]` (the rival pool alone against the real bands, ~1 s a pool). `training_balance -- 0` fingerprints since the talent session: coach 206.798298350 / 14.102831594 / 1226.006524079 (with `progression.dose` = {default 5}, `headroom_span` 5 and no `age_brake_gap` the code gives step 7's 204.145691989 exactly). **Talent balance (GDD 4.2 "Talent balance"):** `Training.dose_scale(id)` (`progression.dose`), `_headroom` over `headroom_span`, `Training.age_share(rate, gap)` (`age_brake_gap`); novice bonus 1.4 → 0.8 (beginner level with trained at 17); `SeasonPlan.template_for(year, phase) / age_class(year) / template(variant, phase, age) / age_group(age)` (`periodization.json age_groups` + each variant's `by_age.<group>.templates`; never read `variants[v].templates` directly for a season); `PlanCards` shows the group line. Rivals: `bloom`, `drift`, `pace` per rival (`races.json rivals` bloom_* / ceiling_drift_* / ceiling_floor / above_ceiling_fall / pace_*; old saves get bloom from the id hash). `career_check.gd` also takes `plan=steady|balanced|ambitious|best` and kinds `story@potential` (e.g. `trained@17.5`), what-ifs on any data path (arrays with `|`), and prints the standards reached, the growth breakdown and the churn; `rival_curves.gd` runs to 25 and prints the churn. - **Day engine (GDD 4.5/4.7):** `Game.date` is *today* (the next day to play); `Game.week_monday()` for week-based code (training tab, plan preview). `Game.advance_day()` plays one day, `Game.advance_week()` plays to Sunday night; both (and `finish_race()`) return `Game.DAY_DONE` / `WEEK_DONE` / `RACE` (race screen, `race_day` set) / `STOP` (unanswered stop event).
